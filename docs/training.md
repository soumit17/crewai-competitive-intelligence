# Training the ShortUpdateCrew with `crewai train`

Generated by `uv run python scripts/compare_trained.py runs/training/short_update.pkl` (spec §17.2, M8d). Week 3's published signals, Haiku 5.5, the same crew run twice; judges Haiku x3 (M8c). Cost $0.0409.

**How training works** (crewai 1.15.33): `crewai train -n 2 -f FILE` runs the crew twice with `human_input` on every task; after each task the agent gets feedback and redoes it; then each agent's own LLM turns its feedback into suggestions, saved by role. The feedback came from `evals/training_feedback.json` (drawn from the M8c eval report) through crewai's human-input provider hook, not typed. A run given the file appends the suggestions to every prompt of that role.

## What training produced

**Market Analyst** (training quality 8.0):
- Rate a threat as high only when a signal changes something this week, such as a new office, a new feature launch, or a real price change, and never for an unchanged price or a re-listed job ad.
- Cite the signal ids for every threat level and base each level only on this week's signals.
- Explicitly label unchanged prices, hiring lists, and repeated roles as not counted or not high impact, and name their ids.
- Separate existing conditions from new moves, for example by stating that a price gap was already present last week.
- Exclude low-credibility rumours by stating the credibility score and the threshold used, such as below 0.5.
- Include recent fixes and rating changes when they affect the competitor's standing this week, and state whether they raise or lower the threat.
- Keep rationales concise and factual, and make sure every signal id listed in signal_ids is cited in the rationale text.

**Brief Writer** (training quality 7.0):
- Never describe a price or plan as the lowest, cheapest, first or only option unless every competitor's signals have been checked for that claim.
- Do not add information the signals do not state, such as adoption figures, impact ratings, or 'new this week' labels without an actual comparison to the prior week's brief.
- Lead the output with the threat to the Kolkata market, placing the highest-impact Kolkata item first in the headline and TL;DR.
- State each point only once across the TL;DR, threats and recommendations; do not restate the same fact in multiple sections.
- Remove unsupported qualifiers such as credibility scores or 'high impact' labels unless the signals explicitly provide them.
- Keep the headline consistent with the Kolkata-first framing and avoid rating changes that the signals do not support, such as moving a company to low without justification.
- Where a claim is hedged in the signals (e.g., 'reportedly'), preserve that hedge in every section where it appears.
- Verify that each price comparison cites the competitor signals it relies on and that unchanged prices are described as unchanged only when prior-week data confirms it.
